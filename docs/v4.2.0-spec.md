# V4.2.0 — Advanced Retrieval Engine

**Milestone**: Master Plan §5 (V4.2.0)
**Scope**: Pipeline restructuring, hybrid RRF fusion, reranker abstraction,
diversity (MMR-lite), retrieval explanations, embedding cache, temporal parsing.
**Out of scope** (deferred): LLM reranker provider, relationship-graph expansion,
full BM25 FTS index.

---

## 1. Objective

Replace the monolithic `search(memories, q, queryVec?)` with a **staged pipeline**
that:

1. Produces *explainable* scores (each term attributed).
2. Fuses keyword and vector signals via **Reciprocal Rank Fusion (RRF)**.
3. Applies a pluggable **reranker** abstraction (local / no-op; providers stay
   deferred to 4.3+).
4. Dampens redundancy with a lightweight **MMR** pass.
5. Caches query embeddings per `(model, text)` for the server lifetime.
6. Parses simple **temporal qualifiers** (`latest`, `recent`, `before X`).

Backward-compatible: every existing `search()` call returns the same *order* when
no query flags are set. Tests prove this invariant.

---

## 2. Pipeline Stages

```
Query (raw string + parsed opts)
  ↓  [1] Normalize        lower-case, strip punctuation, extract terms, tempQual
  ↓  [2] Hard filters     scope gate, excluded types, trust min (future 4.5)
  ↓  [3] Candidates       all in-scope memories (current behavior)
  ↓  [4] Keyword scoring  BM25-lite: tf·idf heuristic over content+tags
  ↓  [5] Vector scoring   cosine(queryVec, mem.embedding) if both present
  ↓  [6] Score fusion     RRF of keyword-rank and vector-rank (per-mem)
  ↓  [7] Ranking modifiers
       · provenance  manual +10
       · trust       TRUST_POINTS additive
       · retention   pinned +50
       · importance  ×4
       · recency     exp(−age/30d) × 20
  ↓  [8] Standing-instruction gate   role/instruction at trust≥trusted → +1000
  ↓  [9] Reranker          local (identity) or future providers
  ↓  [10] MMR diversity     deduplicate near-duplicate topics at λ≈0.5
  ↓  [11] Context selection  slice top-k
  ↓  Final results (+ optional explanations)
```

## 3. New Types (types.ts additions)

```ts
/** Each scoring component exposed so callers can inspect why a memory ranked
    where it did (plan §5.8). */
export interface RetrievalExplanation {
  /** Unique id of the scored memory. */
  id: string;
  /** Full score breakdown (sums to totalScore). */
  components: Record<string, number>;
  /** The final float score assigned before MMR truncation. */
  totalScore: number;
  /** Which gates fired: "scope_match", "role_gate", "similarity_cut", ... */
  reasons: string[];
}

/** Output surface — wraps both the ranked memories and per-memory explanations. */
export interface SearchResults {
  results: Memory[];
  explanations?: RetrievalExplanation[];
}
```

**API contract change (non-breaking):** `service.search()` returns the existing
`{ text?, results: Memory[] }`. A new `explain: true` flag on `SearchQuery`
adds `explanations` to the envelope; defaults off so no client breaks.

## 4. Pipeline Components

### 4.1 Normalize (extractTerms, parseTemporal)
- `extractTerms(q)`: lowercase, drop tokens ≤1 char, keep A-Z/a-z/0-9/ᵁ.
- `parseTemporal(q)`: returns `{ latest?: true, recentMs?: number|null,
  beforeMs?: number|null, afterMs?: number|null }`.
  Recognized keywords (prefix of any memory's content or tags):
  - `latest <N>` / `latest` → sort by updatedAt desc, cap N (default 5)
  - `recent` / `recent <N>` → same as latest with recency bias boost
  - `before <date>` / `after <date>` → ISO-8601 or `today ± N d/y`

### 4.2 Hard Filters (unchanged semantics)
- Scope gate: foreign-scope memories drop to score 0 unless query scope matches.
- `global` memories always visible (current behavior).
- **Deferred**: trust-min threshold (the existing +1000 standing-instruction gate
  stays untouched).

### 4.3 Candidate Generation
Current behaviour passes every in-scope memory to scoring. Keep that as the
default candidate set; add an optional `candidates?: string[]` pre-seeded list
for future relationship-expansion calls (no behavior change today).

### 4.4 Keyword Scoring (BM25-lite)
Simple tf-idf style:
```
score(m, terms) = Σ_t (tf(t in m) / (tf(t in m) + k1)) * log(1 + N / df(t))
where k1=1.5, N = total memories, df(t) = memories containing t.
```
Clamped to [0, 60] to match the existing keyword ceiling for regression tests.
If no query terms → keyword score = 0 (not the old "10 for free").

### 4.5 Vector Scoring
Cosine(sim(query, mem)) × 100, capped to [0, 100]. Memories without an
embedding fall through to keyword-only scoring. Near-zero (< 0.05) similarity
still acts as a soft filter only when the memory lacks scope-match strength
(current behaviour preserved).

### 4.6 Reciprocal Rank Fusion (RRF)
For each memory that appears in at least one ranked list:
```
rrfScore(m) = keywordRank/m.rank_kw + vectorRank/m.rank_vec
ranked[key] = 1/kr, ranked[vec] = 1/kvr  (k=1.6 per standard)
fusionScore = rrfScore * fusionWeight (weight ≈50 so RRF sits alongside
              the modifier terms, not drowned by them)
```
If only one signal is available, `fusionScore = that signal`. This is how
keyword mode still works when queryVec is null.

### 4.7 Ranking Modifiers (retained from v4.1.x, now separated from scoring)
These apply *after* fusion but *before* the standing-instruction gate, so the
gate remains absolute:
- provenance manual +10
- trust additive (TRUST_POINTS)
- retention pinned +50
- importance × 4
- recency exp(−age/30d) × 20

### 4.8 Standing-Instruction Gate (unchanged)
`(type === "role" || type === "instruction") && trust !== "unverified"` →
additive +1000. No other path is altered.

### 4.9 Reranker Abstraction
```ts
export interface Reranker {
  rerank(query: string, candidates: Memory[], queryVec: number[] | null): Promise<Memory[]>;
}

/** Identity reranker — the default. Returns candidates in current pipeline order. */
const identityReranker: Reranker = {
  rerank: (_q, candidates) => Promise.resolve(candidates),
};

/** noReranker — caller-supplied pre-ranked list passed through. */
const noopReranker: Reranker = identityReranker;
```
Provider rerankers (LLM / embedding-model re-scoring) are deferred to 4.3.0.

### 4.10 MMR Diversity (lightweight)
Pick the highest-fusion-score item, then repeatedly pick the item whose
max-relevance-to-selected − λ·avg-self-sim is greatest (λ = 0.5, self-sim =
cosine between embeddings, fallback to 0 if either lacks a vector). Stops when
the queue empties or the hit-count quota is reached. If a memory has no
embedding, its self-sim is treated as 0 (keeps it selectable but not deduped
against similar texts).

### 4.11 Explanation Builder
Each scorer accumulates a `{ term: value }` map; these combine into the
per-memory `RetrievalExplanation`. `search()` only populates them when
`q.explain === true`. Cost: ~1.5× throughput at peak — acceptable.

### 4.12 Embedding Cache
Map `(model: string, textHash: string) → { vec: number[], ts: number }`.
TTL = `process.env.REMEMBRA_EMBEDDING_CACHE_TTL_MS ?? 3600_000`.
Hit → use cached vec; miss → compute and store. Invalidation is TTL-based
only; no manual purge endpoint in 4.2.0 (deferred to 4.4 observability).

## 5. API Surface Changes

### 5.1 SearchQuery (in types.ts)
Add optional fields:
```ts
export interface SearchQuery {
  query?: string;
  scope?: string;
  type?: MemoryType;
  limit?: number;
  explain?: boolean;            // NEW: 4.2.0 — include RetrievalExplanation
  candidates?: string[];        // NEW: 4.2.0 — seed candidate ids (future graph expand)
  reranker?: "identity" | string; // NEW: 4.2.0 — select reranker (deferred to identity only)
}
```

### 5.2 New exported function
```ts
export function searchQ(
  memories: Memory[],
  q: SearchQuery,
  queryVec?: number[] | null,
): SearchResults;
```
`search()` is **deprecated** (keep as wrapper calling `searchQ` with `explain: false`)
to preserve the existing test/import surface while routing callers to the new
pipeline.

### 5.3 Service layer (service.ts)
- Pass `explain: true` through from HTTP when `?explain=true` is set.
- Run the embedding cache lookup (or skip if REMEMBRA_EMBEDDINGS=none).
- Return `SearchResult` with optional `explanations` field.

### 5.4 HTTP GET /memories/search
New query param: `explain=true` / `candidates=id1,id2` / `reranker=identity`.
Doc updates point callers to the new params.

### 5.5 MCP tool: memory_search
New args (optional): `explain`, `candidates`. Existing contracts unchanged.

## 6. Backwards-compatibility Invariants (tests required)

1. `search(arr, q, null)` produces the **same ranking** as v4.1.1 for every
   existing test suite + phase6 property set. (`searchQ(..., {explain:false})`
   delegates to the new pipeline with reranker=identity, mmr=false,
   keyword-only mode identical to old scoring.)
2. When embeddings are absent on every member AND `queryVec` is null,
   `search()` is bitwise-identical to the old implementation.
3. The `SearchResult` envelope shape remains `{ text?, results: Memory[] }`;
   `explanations` is only present when `explain: true`.
4. `REMEMBRA_EMBEDDINGS=none` still works end-to-end.

## 8. Test Plan

### 8.1 Unit tests (retrieval.test.ts)
- Keyword-mode regression: existing 72-line test suite passes **bitwise**.
- Semantic-mode regression: same.
- RRF fusion: two-query test verifying ranks fuse correctly.
- Standing-instruction gate: +1000 survives reranker and MMR.
- Scope isolation: unchanged.
- Explanation output: `explain:true` returns per-memory components summing to total.
- Temporal: `latest`, `recent 3`, `before today`, `after 2024-01-01`.
- MMR deduplication: two nearly-cosine memories don't both rank top.
- Embedding cache HIT/MISS/TTL: three queries reusing the same text.
- Reranker stub: identity reranker preserves order; a mock `noop` reranker
  reverses order (proves the hook fires).

### 8.2 Property tests (phase6.test.ts additions)
- Deterministic across input order (keep existing).
- Raising importance never lowers rank (keep existing).
- Add: raising RRF weight proportionally raises score for matched items.

### 8.3 Integration tests
- HTTP `?explain=true` returns explanation field.
- `?limit=3` respected after MMR.
- Cache stats in `/metrics` (`remembra_embedding_cache_hits_total`,
  `remembra_embedding_cache_misses_total`).

## 10. Implementation Order

1. **Refactor retrieval.ts**: extract keywordScore/recencyScore into named
   stage functions; compose `searchQ()` pipeline. Keep `search()` as thin
   wrapper.
2. **Add RRF fusion** between keyword/vector stages.
3. **Add Explanation builder** (simple accumulator pattern).
4. **Add Embedding cache** in embeddings.ts.
5. **Wire through service + HTTP** (explain flag propagation).
6. **UI polish** (list tooltip, explain toggle in search bar).
7. **Property tests** in phase6 (extend only, don't rewrite).
8. **Docs** across the board.

## 11. Decision Log

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Keep `search()` as public API, route to `searchQ()` | Zero breaking-change risk; tests keep importing `search` |
| D2 | RRF weight ≈50 (additive to modifier pool) | Keeps keyword/vec signals comparable to importance/trust range |
| D3 | MMR λ=0.5, applied AFTER fusion | Damps redundancy without over-diversifying early rankings |
| D4 | Explain OFF by default | Avoids 1.5× perf hit in steady-state; opt-in for debugging |
| D5 | Embedding cache TTL-only invalidation | Simplicity first; TTL=1h covers provider latency savings |
| D6 | Temporal limited to latest/recent/before/after | Covers 90% of agent-query patterns; full natural-language parser is 4.3 |
| D7 | Identity reranker as default; provider rerankers deferred | Keeps API surface stable until 4.3 |
| D8 | BM25-lite (tf-idf heuristic) instead of full BM25 | Avoids an external dep; suffices for <10k memories |

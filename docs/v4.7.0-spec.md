# V4.7.0 — Agent & Multi-Agent Memory

**Plan §10.** Makes Remembra suitable for autonomous AI systems by adding agent identity, session tracking, memory ownership, access control, and council memory support.

---

## Objective

Enable safe shared-memory operation for multiple autonomous agents without mixing identities or scopes.

---

## 10.1 Agent Identity

Extend `Provenance` with:

```typescript
agentType?: string;      // e.g. "researcher", "coder", "critic", "planner", "reviewer"
agentVersion?: string;   // semantic version of the agent that created this memory
```

Existing `agentId` is retained. `agentId` identifies attribution; it is not an authentication credential.

---

## 10.2 Session Identity

Extend `Provenance` with:

```typescript
conversationId?: string;  // group of messages forming one conversation turn
taskId?: string;          // task this memory belongs to
runId?: string;           // single execution/run identifier
```

All optional. Existing `sessionId` and `messageId` are retained.

---

## 10.3 Memory Ownership

Add `owner` to `Memory` and `StoreInput`:

```typescript
owner?: MemoryOwner;  // "user" | "agent" | "project" | "organization" | "global"
```

Default: `"global"` for backward compatibility. Inherited from provenance when absent (`sourceType === "agent"` → `"agent"`, etc.).

---

## 10.4 Shared vs Private Memory

Add `access` field to `Memory`:

```typescript
access?: MemoryAccess;  // "private" | "shared" | "global"
```

- `private`: only visible to the verified agent identity recorded in provenance.
- `shared`: visible to identified agents and still constrained by the normal scope filter.
- `global`: visible everywhere (default).

Access filtering is enabled only by `REMEMBRA_AGENT_MODE=1` or the explicit
`MemoryService({ agentMode: true })` option. The embedding application must
authenticate the caller and supply `AgentContext`; Remembra does not trust a
client-supplied agent header by default. In agent mode, a request without a
verified context can read only `global` memories and receives `NOT_FOUND` for
an inaccessible direct id, preventing existence disclosure.

New env vars:
| Variable | Default | Purpose |
|----------|---------|---------|
| `REMEMBRA_AGENT_MODE` | `0` | enable agent-scoped access filtering |
| `REMEMBRA_DEFAULT_ACCESS` | `global` | default access for new memories |

---

## 10.5 Council Memory

For Hilbras-style multi-agent systems:

```text
Council
├── researcher
├── coder
├── critic
├── planner
└── reviewer
```

Support three conventional scope tiers, using the existing scope isolation
and memory types:
- **agent-specific**: `scope: "agent:{agentId}"` (e.g. `agent:coder`).
- **council**: `scope: "council:{councilName}"`, shared by its members.
- **shared task**: `scope: "task:{taskId}"`, shared by agents on that task.

Council decisions remain `type: "decision"` with the council scope. The
eleven-type semantic model is unchanged.

---

## 10.6 Memory Attribution

Every agent-created memory retains full provenance:

```typescript
provenance: {
  sourceType: "agent",
  agentId: "...",
  agentType: "...",
  agentVersion: "...",
  sessionId: "...",
  conversationId: "...",
  taskId: "...",
  runId: "...",
  messageId: "...",
  provider: "...",
}
```

Agent memories preserve the existing trust-default contract (`trusted` unless
the caller explicitly supplies another trust level). Applications can require
approval by supplying `trust: "unverified"` or updating it after review. Audit
events retain the source agent and the memory's existing audit action.

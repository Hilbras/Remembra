# V5.5.0 Compatibility Report

This release delivers the **roadmap §17–§24 milestone that the plan calls
V5.1.0** — production infrastructure — under version **5.5.0**.

## Why the version is 5.5.0 and not 5.1.0

The roadmap's version matrix assumed V5.1.0, V5.2.0, and V5.3.0 would ship
before V5.4.0. V5.4.0 was released first, so the roadmap's `5.1.0` is now a
*downgrade* of an already-published version. npm would reject it, and
`npm view @hilbras/remembra version` would keep reporting `5.4.0`.

So this milestone ships as **5.5.0**, and the roadmap slots are renumbered:

| Roadmap slot | Old | Now | Status |
|---|---|---|---|
| §17–§24 Production infrastructure | V5.1.0 / V5.1.1 | **V5.5.0** | **this release** |
| §46–§51 Tenancy, RBAC, policy engine | V5.5.0 / V5.5.1 | V5.6.0 / V5.6.1 | not started |
| §52–§58 Performance and scalability | V5.6.0 / V5.6.1 | V5.7.0 / V5.7.1 | not started |
| §59–§64 Enterprise reliability | V5.7.0 / V5.7.1 | V5.8.0 / V5.8.1 | not started |
| §65–§72 Intelligent lifecycle | V5.8.0 / V5.8.1 | V5.9.0 / V5.9.1 | not started |
| §73–§84 V6 preparation | V5.9.0 / V5.9.1 | V6.0.0 / V6.1.0 | not started |
| §85+ Next generation | V6.0.0 | V6.2.0+ | not started |

The intent of every milestone is unchanged; only the numbers moved, and only
because the published order overtook the planned order. **No V5.2 distributed
runtime, no V5.3 advanced retrieval, and no tenancy/RBAC work has been started.**

## What is new

| Area | Change |
|---|---|
| Rate limiting | A `RateLimiter` interface (`check`/`consume`/`reset`, async) with a bounded in-process implementation, injected through `HttpOptions.rateLimiter` |
| Quotas | `REMEMBRA_QUOTAS`: per-dimension policies for organization, project, user, agent, API key, IP, endpoint, and provider, layered on top of the base budget |
| Health | `/health/live`, `/health/ready`, `/health/storage`, `/health/provider`; `/health` unchanged and now cached with single-flight |
| Metrics | p50/p95/p99 over recorded histograms; six new series; seven dead series removed; label cardinality bounded |
| Logging | Request-scoped `requestId`/`operation`/`durationMs` on every line, a field policy that keeps queries and paths out and hashes identities, one `http.request` line per request |
| Shutdown | A bounded, idempotent, honest shutdown sequence in both HTTP and MCP mode |

## Compatibility with V5.4.0

Additive everywhere. No route, field, env var, or default changed meaning, and
no existing behaviour was removed.

### Preserved contracts

- Authentication still precedes any rate-limit consumption, and an
  unauthenticated caller is still charged to a separate anonymous bucket.
- Rate identity is still opaque — a truncated SHA-256 — and
  `rateLimitIdentity` now *enforces* it by refusing any value that is not a hex
  digest.
- `REMEMBRA_RATE_LIMIT` and `REMEMBRA_RATE_WINDOW_MS` still configure the base
  per-identity budget, and with `REMEMBRA_QUOTAS` unset the behaviour is exactly
  V5.4.0's.
- `/health` returns the same shape and the same status codes.
- The capability manifest still describes the **build**, not the deployment.
- `SEC-RL-001`, `SEC-RL-002`, and `SEC-LOG-001` pass unmodified.

### New limits that did not exist in V5.4.0

1. Tracked rate-limit identities are capped at 10,000 by default
   (`REMEMBRA_RATE_MAX_IDENTITIES`) and evicted least-recently-used. V5.4.0
   retained every identity it had ever seen, which was reachable without a
   credential.
2. `/health` and `/health/ready` may answer from a cache up to
   `REMEMBRA_HEALTH_CACHE_MS` old (default 1s). Set it to `0` for a live answer
   on every probe.
3. Log fields named `query`, `text`, `content`, `path`, `root`, `dir`, `file`,
   `filename`, `storagePath`, or `q` are dropped unless `REMEMBRA_DEBUG` is set,
   and `tenantId`/`organizationId`/`projectId`/`userId`/`agentId`/`apiKey` are
   hashed. A deployment that relied on those fields appearing raw must set
   `REMEMBRA_DEBUG`.
4. Seven metrics that V4.6.0 declared and never recorded are gone, because they
   could never report: `remembra_memory_count_{active,archived,deleted}`,
   `remembra_duplicate_rate`, `remembra_conflict_rate`,
   `remembra_stale_memory_rate`, `remembra_estimated_cost_usd`, and
   `remembra_token_usage_total`. A dashboard reading them sees the series absent
   rather than permanently empty — see
   [`v5.1.0-audit.md`](v5.1.0-audit.md) finding M4.

## Bugs found and fixed by the milestone's own audit

Recorded in full in [`v5.1.0-audit.md`](v5.1.0-audit.md); the ones with
security or correctness weight:

1. **Unbounded rate-limiter state, reachable pre-authentication.** A window was
   only reclaimed if its own key was checked again after expiry, so any identity
   used once and abandoned lived for the process lifetime — 50,000 abandoned
   keys retained 50,001 entries. The anonymous bucket is charged before
   authentication and keyed by source address, so no credential was needed.
2. **`/health` was unauthenticated, unrated, and not cheap.** It ran a full
   storage scan, a recovery-state refresh, and a durable recovery-state write on
   every call.
3. **`/metrics` was rate limited despite the source documenting it as exempt**, so
   a scraper lost observability during exactly the rate-limit storms it exists to
   diagnose.
4. **Seven metrics were declared and never written**, so dashboards on them
   rendered empty and looked like data loss.
5. **Two raw-content leaks in logging.** `retrieval.debug` logged the query text
   behind `REMEMBRA_DEBUG_RETRIEVAL` rather than the documented
   `REMEMBRA_DEBUG`; `migration_start` logged a storage path unconditionally.
6. **MCP mode installed no signal handler**, so `SIGTERM` took the default
   disposition and killed an MCP server with no drain and no recovery-state
   flush.
7. **A concurrent burst could bypass the quota.** Decide and charge were
   separated by an `await`, so 500 concurrent requests against an organization
   cap of 20 were all admitted. Found by the stress matrix.
8. **An injected embedding adapter bypassed provider metrics entirely** — the
   path V5.4 most wanted working.

## What is deliberately not claimed

No distributed quotas, no distributed workers, no shared-state runtime, and no
advanced retrieval engine. The delivery queue, the idempotency ledger, and the
rate limiter are all single-host and in-process. The interfaces added here —
`RateLimiter`, the quota contract, `ShutdownCoordinator` — exist so a shared
implementation *can* be added later without changing the request path; adding one
is later work and is not claimed.

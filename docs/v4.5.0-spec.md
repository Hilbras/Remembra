# V4.5.0 — Lifecycle & Memory Intelligence

**Plan §8.** Makes Remembra capable of managing memory quality automatically through multi-signal decay, lifecycle state machine, consolidation, temporal awareness, and automatic validation.

---

## Objective

Move from simple time-based decay to an intelligence-driven lifecycle system that preserves high-value memories, surfaces contradictions, and compresses related items into compact representations while maintaining full provenance.

Every change is additive; no existing API contract shifts.

---

## 8.1 Memory Lifecycle States

```
candidate → active → aging → archived → {quarantined, deleted}
                              ↕
                          revive (manual or auto)
```

| State | Meaning | Search exposure |
|-------|---------|-----------------|
| `candidate` | newly extracted, unverified | not surfaced until trusted |
| `active` | normal operational memory | fully exposed |
| `aging` | past shelf-life but still recoverable | dimmed in search |
| `archived` | preserved offline | excluded by default |
| `quarantined` | flagged sensitive/injected | excluded unless `includeQuarantined` |
| `deleted` | permanently gone | N/A |

Existing retention modes (`pinned`, `persistent`, `ephemeral`, `decaying`, `neverExpire`) remain as **properties**, not lifecycle states — they influence the transition rates between lifecycle states.

New env vars:
| Variable | Default | Purpose |
|----------|---------|---------|
| `REMEMBRA_AGE_THRESHOLD_DAYS` | `30` | days since lastSeens before entering `aging` |
| `REMEMBRA_AGING_BOOST` | `-50` | score penalty applied to aging memories in search |

## 8.2 Multi-Signal Decay Model

Replace single `time > threshold → archive` with a composite health score:

```
health = w_age   * f(age)
       + w_lastSeen * f(lastSeenRecency)
       + w_importance * (importance / 5)
       + w_confidence * confidence
       + w_retrieval * f(retrievalFrequency)
       + w_trust * trustFactor(trust)
       + w_relations * f(relationshipStrength)
```

Defaults (tunable via `REMEMBRA_DECAY_WEIGHTS`):

| Signal | Weight | Notes |
|--------|--------|-------|
| age | 0.15 | inverse: newer is healthier |
| lastSeen | 0.25 | most heavily weighted |
| importance | 0.20 | direct |
| confidence | 0.10 | direct |
| retrievalFrequency | 0.15 | how often it surfaces in searches |
| trust | 0.10 | verified > trusted > unverified |
| relationshipStrength | 0.05 | number of typed relations |

Health score threshold → `aging`. Additional threshold → `archived`.

Configurable via:
| Variable | Default | Purpose |
|----------|---------|---------|
| `REMEMBRA_DECAY_WEIGHTS` | *(auto)* | semicolon-separated `key=value` pairs for above weights |
| `REMEMBRA_HEALTH_AGE_THRESHOLD` | `0.35` | health score below which memory enters aging |
| `REMEMBRA_HEALTH_ARCHIVE_THRESHOLD` | `0.15` | health score below which memory is archived |

## 8.3 Memory Consolidation

On `POST /maintain` (and opportunistically on digest), detect and act on:

| Pattern | Detection | Action |
|---------|-----------|--------|
| **Exact duplicate** | identical type + scope + content hash | skip on ingest; flag during maintain |
| **Near-duplicate** | vector similarity > `REMEMBRA_DUP_SIMILARITY` (default 0.92) within same type+scope | merge content, keep higher importance/confidence |
| **Contradiction** | two memories of same type+scope, vector similarity > threshold, but content semantics oppose | flag both with `meta.contradicted: true`; surface in search with warning |
| **Outdated fact** | new memory contradicts older one with higher importance/confidence | mark older as `supersededBy`, keep both in history |
| **Fragment** | 3+ memories of same type+scope within 7 days, each short | flag for compression |

Results emitted as audit events and returned by `POST /maintain` in a new `consolidated` array.

---

## 8.4 Memory Compression

When 3+ fragments are detected in the same type+scope over a short window, offer to compress:

```
Input:  [fact, global, "User prefers TypeScript", 
         fact, global, "User writes TypeScript code daily",
         fact, global, "User has worked with TypeScript for 3 years"]
Output: [fact, global, "User is an experienced TypeScript developer who writes code daily",
         meta: { compressedFrom: ["id1", "id2", "id3"], compressionAt: "ISO" }
```

Implemented as a new `memory_compress` tool and `POST /memories/compress` endpoint.
Compression requires LLM involvement (same provider as digest). Provenance tracks original sources.

## 8.5 Temporal Knowledge

Extend `Memory` with optional temporal fields:

```typescript
interface Memory extends MemoryMetadata {
  // ... existing fields ...
  /** When this memory's claim becomes valid. */
  validFrom?: string;
  /** When this memory's claim ceases to be valid. */
  validUntil?: string;
  /** When the observation was made (distinct from createdAt when backfilled). */
  observedAt?: string;
  /** ID of the memory that supersedes this one. */
  supersededBy?: string;
}
```

Search respects temporal bounds: memories with `validUntil < now` are excluded unless `includeExpired=true`. Memories with `validFrom > now` are excluded unless `includeFuture=true`.

## 8.6 Automatic Validation

High-value memories (importance ≥ 4 AND trust = "verified") are periodically revalidated:

1. On each decay pass, identify candidates for revalidation
2. Send content + context to LLM with instruction: "Confirm or correct this fact: ..."
3. If confirmed → reset `lastValidated` to now
4. If corrected → update content, bump version, log reason
5. If contradicted → set `trust: "unverified"`, emit `memory.contradicted` event

Configurable via:
| Variable | Default | Purpose |
|----------|---------|---------|
| `REMEMBRA_VALIDATE_INTERVAL_HOURS` | `24` | minimum hours between validations of the same memory |
| `REMEMBRA_VALIDATE_IMPORTANCE_MIN` | `4` | only validate memories with importance ≥ this |

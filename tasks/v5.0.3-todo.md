# V5.0.3 Task List: Reliability and Recovery Hardening

Status: audit complete; recovery-state, startup-validation, snapshot-semantic,
SQLite restore-journal, and durable CLI-migration slices are implemented. Generic
import atomicity, read-only enforcement, and injected crash/disk/permission
coverage remain. V5.0.3 does not authorize V5.1 or V6 implementation.

Source plan: [`v5.0.3-plan.md`](v5.0.3-plan.md)
Master roadmap: [`REMEMBRA_V5_TO_V6_ROADMAP.md`](../REMEMBRA_V5_TO_V6_ROADMAP.md)

## Baseline

- V5.0.2 release commit: `be51dae72556870be82fdee60d2cb8680ae5e5f0`.
- V5.0.2 gates: 431 full tests, 64 security tests, 13 recovery tests,
  36 documentation files, and zero high-severity audit findings on both
  supported Node runtimes.
- V5.0.2 security boundary remains mandatory.

## Phase 0: Audit and contract

- [x] **V5.0.3-T01 — Audit startup, health, recovery, and snapshot paths**
  - Acceptance: current validation, readiness, migration, backup/restore,
    snapshot, and crash behavior is inventoried with concrete gaps and
    compatibility constraints.
  - Verify: focused baseline tests, source audit, and failure matrix.
  - Depends on: V5.0.2 release.
  - Evidence: the recovery-path audit identified startup-order mutation, non-durable states, partial import, the SQLite rename crash window, incomplete snapshot semantics, and missing failure-injection coverage.

- [ ] **V5.0.3-T02 — Freeze readiness states and failure semantics**
  - Acceptance: Healthy/Degraded/Recovering/Failed/ReadOnly transitions,
    public error behavior, and partial-operation semantics are explicit.
  - Verify: contract tests or fixtures for every state and transition.
  - Depends on: V5.0.3-T01.
  - Progress: `REC-STATE-001` covers the pure state vocabulary; durable/read-only transitions remain.

## Phase 1: Startup and state

- [ ] **V5.0.3-T03 — Add deterministic startup validation and health state**
  - Acceptance: configuration, storage path/permissions, database/schema,
    encryption, provider, tenant, and filesystem safety are checked before
    serving; invalid state fails closed.
  - Verify: startup matrix, health output, and V5.0.1 startup regressions.
  - Depends on: V5.0.3-T02.
  - Progress: `REC-START-001` validates policy/provider/key/tenant configuration and probes a safe writable root before CLI backend migration.

- [ ] **V5.0.3-T04 — Add a durable recovery state machine**
  - Acceptance: bounded transitions, checkpoint/resume/failure records, and
    explicit recovery errors are durable and observable.
  - Verify: transition, retry, crash-resume, and read-only tests.
  - Depends on: V5.0.3-T03.

## Phase 2: Data integrity

- [ ] **V5.0.3-T05 — Complete snapshot and backup validation**
  - Acceptance: format, version, integrity, metadata, tenant, memory schema,
    relations, timestamps, and size are validated before mutation.
  - Verify: malformed/partial/cross-tenant/timestamp fixtures.
  - Depends on: V5.0.3-T04.
  - Progress: `REC-SNAP-001` validates timestamps/order, duplicate IDs, self-references, strict tenant dimensions, and the service/API size bound before writes.

- [ ] **V5.0.3-T06 — Make restore and recovery staging atomic**
  - Acceptance: validate → prepare → temporary state → commit → verify;
    interrupted operations leave a verified primary or explicit rollback.
  - Verify: injected write failure, interrupted restore, retained previous,
    and idempotent retry tests.
  - Depends on: V5.0.3-T05.
  - Progress: SQLite restore now writes a journal, verifies post-publication state, and reconciles interrupted staged/previous renames at startup; SQLite snapshot import uses a transaction and file batch import rolls back operational failures. Process-crash resume for ordinary file imports remains.

## Phase 3: Permanent failure coverage

- [ ] **V5.0.3-T07 — Add crash and operational-failure regressions**
  - Acceptance: crash, corruption, partial write, permission failure,

  - Verify: `REC-*` tests are included in the release gate and remain stable on
    Node 18/24.
  - Depends on: V5.0.3-T06.
  - Progress: `REC-FAIL-001` covers injected SQLite transaction failure and file-batch rollback; ENOSPC/EACCES/SIGKILL worker coverage remains.

## Phase 4: Release

## Stop conditions

- [ ] No V5.1 or V6 implementation starts before the V5.0.3 release gate.
- [ ] No security/recovery regression is skipped, deleted, or weakened.
- [ ] No invalid primary store is overwritten without verification.
- [ ] No health/readiness state silently masks corruption or permission loss.
- [ ] No release occurs with a partial destructive operation or unresolved
  critical/high finding.

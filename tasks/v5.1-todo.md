# V5.1.0 Task List: Production Infrastructure

Status: planning started after the V5.0.3 release (`324a645`, Node 18/24 gates
green). V5.2 distributed runtime work is explicitly out of scope until the V5.1
release gate passes.

Source plan: [`v5.1-plan.md`](v5.1-plan.md)

## Phase 0: Audit and contracts

- [ ] **V5.1-T01 — Audit infrastructure paths**
  - Acceptance: rate limiting, quotas, health, metrics, logging, and shutdown
    gaps are recorded with compatibility and security implications.
  - Verify: focused baseline tests and source audit.
  - Depends on: V5.0.3 release.

## Phase 1: Rate and quota foundations

- [ ] **V5.1-T02 — Add RateLimiter abstraction**
  - Acceptance: `check`, `consume`, and `reset` are async, typed, bounded, and
    injectable; current authentication-before-rate-limit behavior and legacy
    callers remain compatible.
  - Verify: focused identity/window/reset tests plus SEC-RL/SEC-AUTH regressions.
  - Depends on: V5.1-T01.

- [ ] **V5.1-T03 — Define distributed-ready quota contract**
  - Acceptance: global, organization, project, user, agent, API-key, IP,
    endpoint, and provider dimensions have typed policies and precedence;
    absent trusted dimensions cannot widen a quota identity.
  - Verify: quota matrix, bypass tests, and configuration validation.
  - Depends on: V5.1-T02.

## Phase 2: Health and observability

- [ ] **V5.1-T04 — Separate health APIs**
  - Acceptance: preserve `/health`; add bounded `/health/live`,
    `/health/ready`, `/health/storage`, and `/health/provider` contracts with
    explicit authentication and no secret/memory disclosure.
  - Verify: route/status/state/fallback/redaction tests.
  - Depends on: V5.1-T01.

- [ ] **V5.1-T05 — Complete production metrics**
  - Acceptance: request, rate-limit, memory, provider, storage, snapshot, and
    recovery metrics use bounded labels and expose p50/p95/p99 where useful.
  - Verify: exposition, reset isolation, and cardinality tests.
  - Depends on: V5.1-T01, V5.1-T04.

- [ ] **V5.1-T06 — Standardize structured request logging**
  - Acceptance: request/operation metadata uses centralized redaction; raw
    queries, secrets, and unbounded tenant values never enter logs.
  - Verify: structured schema and adversarial log tests.
  - Depends on: V5.1-T01.

## Phase 3: Lifecycle and hardening

- [ ] **V5.1-T07 — Implement bounded graceful shutdown**
  - Acceptance: stop intake, drain active work with a deadline, stop jobs,
    flush observability, and close providers/storage without hanging.
  - Verify: in-flight, timeout, repeated-signal, and cleanup tests.
  - Depends on: V5.1-T04, V5.1-T05, V5.1-T06.

- [ ] **V5.1-T08 — Add production stress coverage**
  - Acceptance: concurrency, large payload/search, provider timeout storms,
    rate-limit storms, database contention, shutdown/restart under load, and
    resource-leak checks are bounded and reproducible.
  - Verify: dedicated stress matrix on Node 18.20.8 and 24.21.0.
  - Depends on: V5.1-T02–T07.

## Phase 4: Release

- [ ] **V5.1-T09 — Document and release V5.1.0**

## Checkpoints

- [ ] Existing SEC-RL/SEC-AUTH/SEC-LOG/SEC-SENS regressions remain green.
- [ ] No public identity field can select or widen quota identity.
- [ ] Health, metrics, and logs are bounded and secret-safe.
- [ ] Shutdown and stress evidence passes on Node 18.20.8 and 24.21.0.
- [ ] No V5.2 implementation starts before V5.1-T09 passes.

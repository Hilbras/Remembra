## Phase 1: Rate and quota foundations

- [x] **V5.1-T02 — Add RateLimiter abstraction**
  - Acceptance: `check`, `consume`, and `reset` are async, typed, bounded, and
    injectable; current authentication-before-rate-limit behavior and legacy
    callers remain compatible.
  - Verify: focused identity/window/reset tests plus SEC-RL/SEC-AUTH regressions.
  - Depends on: V5.1-T01.
  - Progress: complete. The request path now depends on the `RateLimiter`
    interface, injected via `HttpOptions.rateLimiter`, with
    `InProcessRateLimiter` as the shipped implementation — so V5.2 can supply a
    shared-store limiter without editing `http.ts`. `check` and `consume` are
    distinct, so a speculative check no longer spends quota. State is bounded:
    a `maxIdentities` ceiling plus a deterministic expiry sweep and LRU
    eviction replaced the old `Math.random()` pruning, and the audit's
    50,001-entry reproduction is now 10,000 (40,000 evicted).
    `rateLimitIdentity` rejects any value that is not a hex digest, so a raw
    principal or API key fails loudly instead of becoming a quota key. Tenant
    dimensions are named (`organization=`, `user=`, …) and stay hashed.
    22 new tests: `RL-001`–`RL-009` unit and `RL-HTTP-001`–`RL-HTTP-006`
    parity. SEC-RL-001 and SEC-RL-002 pass unchanged, and
    `REMEMBRA_RATE_LIMIT` / `REMEMBRA_RATE_WINDOW_MS` still configure the
    default limiter.

- [x] **V5.1-T03 — Define distributed-ready quota contract**
  - Acceptance: global, organization, project, user, agent, API-key, IP,
    endpoint, and provider dimensions have typed policies and precedence;
    absent trusted dimensions cannot widen a quota identity.
  - Verify: quota matrix, bypass tests, and configuration validation.
  - Depends on: V5.1-T02.
  - Progress: complete. `src/quota.ts` defines `QuotaPolicy`, `QuotaPolicies`,
  `parseQuotaPolicies` for `REMEMBRA_QUOTAS`, and `QuotaRateLimiter`, which
  composes one bounded `InProcessRateLimiter` per dimension so the ceiling
  cannot multiply. Precedence is the declared `RATE_LIMIT_DIMENSIONS` order with
  the base budget last, so the same exhausted state always reports the same
  dimension; a 429 can now be attributed rather than being anonymous.
  Charging is all-or-nothing, so a request denied by one dimension is not
  charged to the others. Two rules keep it fail-closed: the base per-identity
  budget is charged for every request, so adding a policy can only make a
  deployment stricter, and a dimension is charged only when the request carries
  a trusted value for it — an absent dimension falls back to the base budget
  rather than escaping it. `QUOTA-006b` pins that a request missing all eight
  configured dimensions is charged once, not nine times, which is a bug the
  first implementation had. 20 tests: `QUOTA-001`–`QUOTA-015` and
  `CONFIG-001`–`CONFIG-004`, covering the nine-dimension matrix, ten distinct
  configuration failures that each name the variable and the entry, and
  all-or-nothing charging.

## Phase 2: Health and observability

- [x] **V5.1-T04 — Separate health APIs**
  - Acceptance: preserve `/health`; add bounded `/health/live`,
    `/health/ready`, `/health/storage`, and `/health/provider` contracts with
    explicit authentication and no secret/memory disclosure.
  - Verify: route/status/state/fallback/redaction tests.
  - Depends on: V5.1-T01.
  - Progress: complete. `/health/live` is public and cheap — process state only,
    no storage read and no durable write — so it reports `200` even when
    storage is broken, and reports `draining: true` once `beginShutdown()` is
    called so an orchestrator can take the instance out of rotation.
    `/health/ready`, `/health/storage`, and `/health/provider` are handled after
    authentication and rate limiting, so they inherit the existing rules
    without duplicating any auth code. `/health` keeps its exact response shape
    and status codes; the audit's concern that an unauthenticated caller could
    drive a storage read and a recovery-state write per request is addressed with
    a short cache plus single-flight, verified by counting backend scans: 25
    sequential probes cost one scan, 20 concurrent probes cost one scan, and
    `REMEMBRA_HEALTH_CACHE_MS=0` restores a live answer per probe. Failures are
    cached too, so a broken disk is not hammered. No health response carries
    memory content, a storage path, an error message, or a provider key —
    `HEALTH-002`, `HEALTH-007`, and `HEALTH-008` assert the negatives. The
    route-parity test caught the three new authenticated routes as
    undocumented, so `docs/openapi.yaml` gained the paths plus `StorageHealth`
    and `ProviderHealth` schemas. 15 tests: `HEALTH-001`–`HEALTH-014`.

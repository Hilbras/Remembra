# V5.4.0 Task List: Developer Platform

Status: planning started after the V5.0.3 release. V5.1–V5.3 remain
unfinished; this phase is additive and does not claim their distributed
capabilities. V5.5 and V6 remain out of scope.

Source plan: [`v5.4-plan.md`](v5.4-plan.md)

## Phase 0: Audit and contracts

- [x] **V5.4-T01 — Audit developer-platform surfaces**
  - Acceptance: API, SDK, batch, webhook, Python, OpenAPI, examples, and
      compatibility gaps are recorded before implementation.
  - Verify: source audit, endpoint inventory, and clean package smoke tests.
  - Depends on: V5.0.3 release.
  - Progress: the audit confirmed `/api/v1` compatibility, partial TypeScript
    SDK/batch support, and missing Python/webhook/OpenAPI/example surfaces.

## Phase 1: Versioned API and TypeScript SDK

- [x] **V5.4-T02 — Freeze API versioning and compatibility metadata**
  - Acceptance: existing `/api/v1` and legacy behavior remain compatible;
      version metadata is bounded and future `/v2` rules are documented.
  - Verify: route/header/package smoke tests.
  - Depends on: V5.4-T01.
  - Progress: added the dependency-free `api-contract` source of truth,
    authenticated `GET /api/v1/capabilities`, shared SDK constants/method, and
    package export; legacy routes and `/api/v1` headers remain unchanged.

- [ ] **V5.4-T03 — Harden the TypeScript SDK**
  - Acceptance: memory/snapshot operations, pagination, retries, timeouts,
      aborts, request IDs, and normalized errors are typed and bounded.
  - Verify: SDK contract, retry, cancellation, and error tests.
  - Depends on: V5.4-T02.

## Phase 2: Batch and events

- [ ] **V5.4-T04 — Freeze batch API semantics**
  - Acceptance: limits, partial outcomes, idempotency, and transaction policy
      are explicit across service, HTTP, and SDK.
  - Verify: boundary, duplicate, retry, and partial-failure tests.
  - Depends on: V5.4-T02, V5.4-T03.

- [ ] **V5.4-T05 — Add signed webhook delivery**
  - Acceptance: HMAC, timestamp/replay protection, redacted payloads, bounded
      retries, and durable delivery state are implemented and tested.
  - Verify: signature/tamper/replay/retry/leak tests.
  - Depends on: V5.4-T01, V5.4-T04.

## Phase 3: Python and DX

- [ ] **V5.4-T06 — Add synchronous/asynchronous Python SDKs**
  - Acceptance: typed parity, structured exceptions, retries, timeouts, and
      pagination are verified from a clean package install.
  - Verify: Python unit/integration and package smoke tests.
  - Depends on: V5.4-T02–T04.

- [ ] **V5.4-T07 — Complete docs, OpenAPI, and examples**
  - Acceptance: quick start, API reference, examples, migration, and troubleshooting
      links are current and executable.
  - Verify: docs checker and example smoke tests.
  - Depends on: V5.4-T02–T06.

## Phase 4: Release

- [ ] **V5.4-T08 — Document and release V5.4.0**
  - Acceptance: Node/Python release gates, artifacts, tags, GitHub Release,
      package installs, and compatibility report agree.
  - Depends on: V5.4-T07.

## Checkpoints

- [ ] Existing V5.0.3 security/recovery regressions remain green.
- [ ] SDK retries cannot duplicate unsafe writes.
- [ ] Webhook replay and secret-redaction tests are permanent.
- [ ] No V5.5 or V6 implementation is started by this task list.

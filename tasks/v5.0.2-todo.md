# V5.0.2 Task List: Security Consistency and Policy Hardening

Status: identity isolation, centralized authorization, provider-boundary
regressions, encryption documentation, and the final threat model are complete;
release gates remain. V5.0.3 and later releases are not authorized by this
checklist.

Source plan: [`v5.0.2-plan.md`](v5.0.2-plan.md)
Master roadmap: [`REMEMBRA_V5_TO_V6_ROADMAP.md`](../REMEMBRA_V5_TO_V6_ROADMAP.md)

## Phase 0: Audit and contract

- [x] **V5.0.2-T01 — Audit current identity and authorization paths**
  - Acceptance: every service, HTTP, MCP, SDK, batch, job, snapshot, and direct backend consumer of tenant context is inventoried; user/agent/project gaps are reproduced or explicitly ruled out.
  - Verify: focused baseline tests, source audit, and a recorded compatibility/security finding list.
  - Depends on: V5.0.1 release.
  - Evidence: the V5.0.1/V5.0.2 source audit identified unenforced user/agent dimensions, split authorization, export bypass, stale membership, and provider/encryption documentation gaps.

  - Acceptance: organization is the root boundary; optional dimensions are conjunctive; absence never widens access; organization-wide access requires an explicit trusted capability; provenance agent IDs remain non-authoritative.
  - Verify: file and SQLite tests for point reads, search/candidates, context, history, relations, export, and legacy mode.
  - Depends on: V5.0.2-T01.
  - Evidence: exact user/agent/project predicates, direct-filter default deny, admin-selector scoping, file history checks, entity visibility, and service/backend fixtures are covered.

## Phase 1: Central authorization policy

- [x] **V5.0.2-T03 — Add a pure centralized authorization evaluator**
  - Acceptance: closed operation/permission types, deterministic allow/deny decisions, bounded non-sensitive reasons, explicit capability mapping, and no I/O/content inspection.
  - Verify: unit/table tests for every operation, default deny, dimension intersection, stale membership, and malformed context.
  - Depends on: V5.0.2-T02.
  - Evidence: `src/authorization.ts` and permanent `SEC-AUTH-001/002` tests cover capability mapping, exact dimensions, export separation, and default deny.

- [x] **V5.0.2-T04 — Route protected operations through the evaluator**
  - Acceptance: service methods and HTTP/MCP/SDK/batch/job/snapshot adapters use the same evaluator before provider calls, reads that could leak data, or writes; cross-tenant lookups remain non-informative.
  - Verify: route/service matrix, before-provider side-effect tests, batch/job reauthorization, snapshot/export tests, and V5.0.1 regressions.
  - Depends on: V5.0.2-T03.
  - Evidence: service/entity/MCP paths, selected export, scoped migration, membership revalidation, provider sanitization, and non-informative lookup tests are in the V5.0.2 matrix.

## Permanent regression candidates

- `SEC-AUTH-001`: user and agent selectors cannot widen visibility.
- `SEC-AUTH-002`: missing capabilities and ambiguous principals fail closed.
- `SEC-AUTH-003`: protected paths use the central evaluator before side effects.
- `SEC-AUTH-004`: cross-tenant and unauthorized lookups are non-informative.
- `SEC-AUTH-005`: public provider errors expose no internal diagnostics.
- `SEC-SENS-001`: sensitive-data redaction is applied before store/update/import side effects.
- `SEC-DOC-001`: encryption documentation matches the implementation.

Existing V5.0.1 IDs remain mandatory:

`SEC-RL-*`, `SEC-LOG-*`, `SEC-STORAGE-001`, `SEC-PATH-001`,
`SEC-SNAPSHOT-001`, `SEC-TENANT-001`.

## Stop conditions

- [ ] No V5.0.3, V5.1, or V6 implementation starts before this release gate.
- [ ] No security regression is skipped, deleted, or weakened.
- [ ] No user/agent/project visibility gap remains on a supported backend/path.
- [ ] No public provider error exposes internal URLs, credentials, bodies, or stack traces.
- [ ] No documentation claims encryption for an unimplemented data plane.
- [ ] No release occurs with an unresolved critical/high audit finding.
